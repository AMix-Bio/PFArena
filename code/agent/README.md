# Biomni Agent (clean release)

This release-ready Biomni multi-turn agent package contains only the T1–T4 tasks, DeepSeek/GPT/Claude support (Claude requires an OpenAI-compatible gateway), and the official `evaluation` evaluator.

## Installation and data

```bash
pip install -r requirements.txt
cp .env.example .env                 # Template only; export variables in the shell and never commit real keys
export BIOMNI_PROJECT_ROOT=/path/to/biomni
export BIOMNI_DATA_ROOT=/path/to/benchmark/data
```

You can also override paths directly with `--data-dir` and `--ground-truth-dir`. API keys are read only from environment variables, and logs are automatically redacted. Do not place keys in command lines, code, or result files.

## Usage

```bash
# smoke test: run one sample only
python run.py --task T1_single_mutant_generation --provider deepseek \
  --data-dir "$BIOMNI_DATA_ROOT/T1_single_mutant_generation" \
  --max-items 1 --no-use-tool-retriever \
  --output-csv results/t1_predictions.csv

# GPT / Claude: replace the provider; you may also pass --agent-llm, --agent-base-url, and --agent-api-key-env explicitly
python run.py --task T2_measurement_free_multi_mutant_ranking --provider gpt --data-dir /path/to/T2
python run.py --task T3_anchor_informed_multi_mutant_ranking --provider claude --data-dir /path/to/T3
```

Each task also has a standalone entry script, such as `run_T1_single_mutant_generation_agent_native.py`.

## GPU dispatch (optional)

GPU dispatch forwards GPU-intensive Biomni tool calls to another GPU machine. The agent runner handles model conversations and task orchestration; the GPU worker performs the computation and returns the results. This package includes the client hooks, worker, and runtime helpers, but no internal dispatcher addresses, model weights, or cluster configuration.

GPU dispatch is disabled by default. You can run tasks directly when remote GPU resources are not required:

```bash
python run.py --task T1_single_mutant_generation --provider gpt \
  --data-dir /path/to/T1 --max-items 1 --no-gpu-dispatch
```

To enable it, first deploy a compatible HTTP dispatcher/worker on a GPU machine, then set the following variables on the runner:

```bash
export BIOMNI_GPU_DISPATCH_ENABLED=1
export BIOMNI_GPU_DISPATCH_BASE_URL=http://your-dispatcher-host:25000
export BIOMNI_GPU_DISPATCH_JOBS_DIR=/path/to/shared/gpu_dispatch_jobs

python run.py --task T1_single_mutant_generation --provider gpt \
  --data-dir /path/to/T1 \
  --gpu-dispatch \
  --gpu-dispatch-base-url "$BIOMNI_GPU_DISPATCH_BASE_URL" \
  --gpu-dispatch-jobs-dir "$BIOMNI_GPU_DISPATCH_JOBS_DIR"
```

Related options:

- `--gpu-dispatch` / `--no-gpu-dispatch`: enable or disable forwarding
- `--gpu-dispatch-base-url`: dispatcher HTTP endpoint
- `--gpu-dispatch-jobs-dir`: job directory shared by the runner and worker
- `--gpu-dispatch-timeout-seconds`: timeout for an individual GPU job; `0` inherits the task timeout
- `--gpu-dispatch-functions`: optional list restricting which functions may be forwarded
- `--gpu-dispatch-code`: whether to forward GPU-heavy Python/Bash blocks generated by the agent

The GPU worker must use the same shared job directory as the runner. Configure CUDA, Biomni, model caches, and offline model paths on the worker machine separately. Keep GPU dispatch disabled when no dispatcher is available.

### Runtime arguments

Arguments are defined in `parse_args()` in `agent_native_common.py`; `run.py` selects the task and provider. Common options are:

| Option | Default | Purpose |
| --- | --- | --- |
| `--data-dir` | `BIOMNI_DATA_ROOT/<task>` | Input data directory |
| `--output-csv` / `--audit-jsonl` / `--a1-log` | Corresponding files under `results/` | Prediction, audit, and log outputs |
| `--agent-llm` | `deepseek-v4-pro` | Model name; `--provider` sets a common preset |
| `--agent-base-url` | Environment variable | OpenAI-compatible endpoint |
| `--agent-api-key-env` | `OPENAI_API_KEY` | Environment variable containing the key |
| `--agent-max-tokens` | `8192` | Maximum output tokens per model call |
| `--max-tool-rounds` | `40` | Maximum number of tool-call rounds |
| `--timeout-seconds` | `1200` | Per-task timeout |
| `--max-items` | All | Number of samples for smoke or batched runs |
| `--no-use-tool-retriever` | Retriever disabled | Reduce additional model calls |

For the complete option list:

```bash
python run.py --task T1_single_mutant_generation --help
```

## Evaluation

```bash
python -m evaluation.evaluate \
  --setting T1_single_mutant_generation \
  --predictions results/t1_predictions.csv \
  --ground-truth-dir /path/to/T1_single_mutant_generation \
  --output-dir results/t1_eval --lenient
```

For strict evaluation, omit `--lenient`. Evaluation outputs include `summary_metrics.json/csv` and `per_assay_metrics.csv`.

## Security and reproducibility

The repository contains no credentials, private paths, experimental results, or model weights. Before committing, run `git diff --check` and search for terms such as `sk-` and `api_key`. Inject credentials through environment variables or a secret-management service.
